Strict "Not Found" Fallback Mechanism

Whenever an employee asks a question regarding information outside the manual (e.g. Q3: Health insurance premium amount or Q4: Current GST rate in India), the pipeline triggers the Hallucination Guard. Rather than inventing numbers or guessing external data, the system strictly returns "Not found" with citation "Not found in document".

Zero-Bleed Page Metadata

Text chunking is performed page-by-page rather than concatenating the entire text corpus. This prevents text from different policies bleeding into each other and ensures that every chunk citation points 100% reliably to the exact page number of the original document.

Offline & Self-Contained Reliability

The vector store operates with sub-millisecond query execution, zero external network dependency, and persistent storage in the local chroma_db/ directory.

Enso Group HR Policy Assistant — Documentation & Flow

Overview

This project implements a Retrieval-Augmented Generation (RAG) assistant over the 79-page Enso Group HR Policy Manual using Python + ChromaDB + LangChain.

Project Structure

hr-policy-assistant/
├── README.md               # Complete architecture & submission docs
├── requirements.txt        # Python dependencies (chromadb, langchain, etc.)
├── data/
│   ├── hr_manual.pdf       # 79-page official HR Manual PDF
│   ├── hr_manual_extracted.json # Full parsed text with page tags
│   └── answers_submission.json  # 5 benchmark answers with citations
├── src/
│   ├── config.py           # Settings, paths, hyperparameters
│   ├── document_processor.py # PDF loader & Recursive splitter
│   ├── vectorstore.py      # ChromaDB persistent collection & HNSW search
│   ├── rag_engine.py       # Grounded RAG reasoning & "Not found" guard
│   ├── benchmark.py        # Automated 5-question test runner
│   └── server.py           # FastAPI backend & static server
├── static/                 # Interactive executive UI
└── tests/                  # Pytest test suite

Running the Backend & UI
